## 审批流程说明

### 撤销归档审批流程

```医生/护士申请撤销归档    ↓科主任审核（如配置医务审批流）    ↓医务科审核（如配置医务审批流）    ↓病案室审核    ↓审核通过 → 解锁病历审核驳回 → 结束流程```
**流程说明**：

| 环节 | 说明 |
|------|------|
| 申请 | 医生或护士提交撤销归档申请，说明撤销原因 |
| 科主任审核 | 科主任审核申请，决定是否同意撤销 |
| 医务科审核 | 医务科审核申请，进行最终审批 |
| 病案室审核 | 病案室审核申请，确认可以撤销 |
| 解锁病历 | 审核通过后，解锁病历供医生修改 |

## 数据流向说明

### 电子病案归档数据流向

```[业务系统] → 生成PDF病历    ↓[FTP/OSS] → 存储PDF文件    ↓[无纸化系统] → 下载PDF    ↓[MinIO] → 加密存储    ↓[完整性校验] → 校验通过    ↓[自动编目] → 生成页码    ↓[归档锁定] → 锁定业务系统```
**数据来源**：业务系统（EMR、LIS、PACS等）
**数据存储**：MinIO对象存储（加密）
**数据输出**：锁定信号发送至业务系统

## 功能边界说明

### 本模块负责范围
- 病案归档全流程管理
- 电子病历的采集、下载、存储
- 撤销归档的申请、审核、执行
- 与业务系统的接口对接

### 本模块不负责范围
- 病案审核（由BAW02电子病案审核模块负责）
- 病案借阅（由BAW04电子病案借阅模块负责）
- 病案封存（由BAW05电子病案封存模块负责）
- CA签章（由BAW02电子病案审核模块负责）
- 病案复印（由BAW03电子病案复印模块负责）

### 模块间协作关系
- 归档完成后 → 触发BAW02审核
- 审核通过后 → 触发CA签章（BAW02）
- 修改病案需要 → 通过本模块撤销归档

## 需求评估指南

### 新增需求评估流程

1. **识别需求所属子模块**：根据需求描述，确定属于哪个子模块
   - 电子病案归档
   - 电子文档数据采集
   - 电子病历存储
   - 电子病案修改

2. **功能查重**：在上述功能列表中查找是否已有类似功能

3. **需求类型评估**：
   - 新增功能：功能清单中不存在
   - 功能增强：功能清单中存在，但需要扩展
   - 功能修改：功能清单中存在，但需要调整
   - 重复需求：功能清单中已存在

4. **影响分析**：
   - 对采集系统的影响：是否需要新增接口
   - 对存储系统的影响：是否需要扩容
   - 对业务系统的影响：是否需要修改接口
   - 对其他模块的影响：是否影响审核、借阅等

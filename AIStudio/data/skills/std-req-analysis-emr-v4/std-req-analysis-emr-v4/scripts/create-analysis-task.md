# 创建需求分析任务

正式详细需求分析完成后，默认检查并创建 `需求分析_<需求号>` 子任务。

## 执行原则

- 创建前必须先检查当前需求下是否已有同名或同类需求分析任务。
- 已存在时跳过，不重复创建。
- 优先使用当前会话 TFS MCP 能力创建任务。
- 如果当前环境提供了已配置的专用任务创建脚本，也可以使用该脚本；脚本路径应来自本机配置或用户明确提供，不要在技能中写死个人电脑路径。
- 不要使用通用工作项创建逻辑绕过必填字段。

## 可选命令

```bash
node <create-analysis-task.mjs路径> <需求号> [项目名称]
```

仅当当前电脑已经配置该脚本时使用命令方式；否则使用 TFS MCP 的工作项创建和父子关联能力。

## 创建要求

| 字段 | TFS 引用名 | 要求 |
| --- | --- | --- |
| 工作项类型 | — | 任务 |
| 标题 | System.Title | `需求分析_<需求号>` |
| 父项 | — | 当前 TFS 需求 |
| 专业 | Microsoft.VSTS.Common.Discipline | 分析 |
| 完成日期 | Microsoft.VSTS.Scheduling.FinishDate | 按专用脚本默认规则 |

## 失败处理

- 任务创建失败不回滚已完成的 `Winning.Demand.Analysis` 回写。
- 最终回复中说明任务创建失败原因和建议人工处理动作。

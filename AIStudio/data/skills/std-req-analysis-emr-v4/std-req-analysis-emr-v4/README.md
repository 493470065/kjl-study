## 用途

- 基于 TFS 需求号完成正式产品业务分析。
- 读取 TFS 描述、附件、图片、前置/相关工作项、功能清单、参数和代码现状。
- 生成并回写 `Winning.Demand.Analysis`。
- 追加 `AI-ANALYSIS` 和 `std-req-analysis-emr-v4` 标签。
- 上传最终版 `产品业务分析.md`。
- 默认检查并创建 `需求分析_<需求号>` 子任务，已存在则跳过。

## 复制到其他电脑后的配置

把整个 `std-req-analysis-emr-v4` 目录复制到目标 Agent 的 skills 目录后，通常只需要检查以下配置。

### 1. TFS MCP

目标环境必须已配置可读写 TFS 的 MCP 能力，至少需要支持：

- 读取工作项详情；
- 列出和下载附件；
- 读取相关/父子工作项；
- 从 Markdown 文件路径回写 `Winning.Demand.Analysis`；
- 更新 `System.Tags`；
- 上传附件；
- 创建或关联需求分析任务。

如果 TFS MCP 不可用，本技能会停止，不会改用未认证脚本或旧文件继续分析。

### 2. 代码路径

编辑 `config/codebase-paths.json`，把路径改成当前电脑上的代码目录。当前文件中保留的是参考路径：

| 产品线 | 后端路径 | 前端路径 |
| --- | --- | --- |
| 病案 | `E:\winning\workspace\winning-record` | `E:\winning\workspace\winning-record-web` |
| 病历 | `E:\winning\workspace-bl\winnexCode` | `E:\winning\workspace-bl\winnexCode` |

其他人如果代码不在这些目录，只需要修改：

- `medicalArchive.codeBasePath`
- `medicalArchive.frontendCodeBasePath`
- `medicalRecord.codeBasePath`
- `medicalRecord.frontendCodeBasePath`

不要修改 JSON 为带 `//` 或 `/* */` 注释的格式；说明文字请写在 `_comment` 或 `description` 字段。

### 3. 参数库

参数库配置默认使用团队共用只读连接，通常不需要修改：

- 病案参数：`config/ma-parameter-db.json`
- 病历参数：`config/inpatient-emr-parameter-db.json`

如果目标电脑无法访问对应数据库，分析时会优先使用 `references/Param/` 下的 CSV 参数资料，并记录参数查询失败原因。

病历参数配置中的 `driverJar` 是 Oracle JDBC 驱动路径。如果目标电脑没有相同 Maven 缓存路径，可改成当前电脑实际的 `ojdbc8` jar 路径；不影响病案参数查询。

## 边界

- 必须有 TFS 需求号。
- 只以当前 TFS 工作项、附件/图片、前置/相关工作项、功能清单、参数和代码现状为输入；不依赖其他技能、历史草稿或本地过程文件。
- 不生成研发实现方案、接口设计、数据库设计或开发计划。
- 不处理时限讨论。
- 不创建临时澄清附件。

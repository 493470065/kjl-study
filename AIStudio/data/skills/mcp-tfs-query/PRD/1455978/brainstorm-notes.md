# Brainstorm 分析笔记 - 需求 1455978

## 需求理解

### 问题描述
- 患者综合查询不显示急诊医生站写的病历状态
- 急诊医生站的病历状态是实时查的病历接口获取的
- 门诊是病历状态变更时会调用门诊接口，最终把状态落到门诊的表里
- 急诊产生的病历状态没有落库，所以患者综合查询无法展示

### 解决方案
需要急诊像门诊一样，在病历状态变更时调用接口通知急诊病历状态变更，将状态落库。

## 功能边界分析

### 涉及模块
1. **急诊病历模块** (winning-emr-emg-emrset)
   - 需要在病历状态变更时触发通知
   - 需要调用门诊接口或网关接口

2. **门诊病历模块** (winning-emr-opt-emrset)
   - 可能需要提供接收急诊病历状态变更的接口
   - 需要将急诊病历状态存储到门诊表

3. **网关模块** (winning-ias-biz-gateway-emr)
   - 可能需要作为中间层，协调急诊和门诊的调用

### 新增功能
- 急诊病历状态变更通知机制
- 急诊病历状态落库机制
- 患者综合查询接口改造（如需要）

### 修改现有功能
- 急诊病历状态变更逻辑
- 可能需要修改患者综合查询的数据源

## 数据流分析

### 当前数据流（急诊）
```
急诊医生站 → 急诊病历状态变更 → 仅更新急诊本地状态
                                    ↓
                            患者综合查询（实时接口）→ 无法获取急诊状态
```

### 目标数据流
```
急诊医生站 → 急诊病历状态变更 → 调用状态通知接口
                                    ↓
                            门诊/网关接收状态 → 落库到门诊表
                                    ↓
                            患者综合查询 → 从门诊表查询 → 显示急诊状态
```

### 前端需要调整
- 可能需要调整患者综合查询的数据展示逻辑

## 风险点

1. **接口调用可靠性**
   - 风险：急诊调用门诊接口失败，导致状态不同步
   - 应对：实现重试机制、补偿机制、日志记录

2. **数据一致性**
   - 风险：急诊本地状态和门诊表状态不一致
   - 应对：实现对账机制、定时同步

3. **性能影响**
   - 风险：每次状态变更都调用外部接口，可能影响急诊病历操作性能
   - 应对：考虑异步处理、批量处理

4. **兼容性问题**
   - 风险：需要兼容现有急诊病历操作流程
   - 应对：通过配置开关控制新功能

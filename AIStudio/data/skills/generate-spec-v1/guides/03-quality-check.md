# 03 — 质量自检指南

本指南覆盖 Phase 1 和 Phase 2 完成后的质量自检流程，确保每份产出符合 R0~R13 强制规则。

---

## 1. 自检总流程

```
Phase 1 完成
    │
    ▼
Phase 1 自检（第2节）── 不通过 ──> 修正后重新自检
    │
    通过
    │
    ▼
Phase 2 逐个功能点完成
    │
    ▼
Phase 2 单点自检（第3节）── 不通过 ──> 修正后重新自检
    │
    通过
    │
    ▼
Phase 间交叉检查（第4节）── 不通过 ──> 修正后重新自检
    │
    通过
    │
    ▼
交付
```

> Phase 1 自检 = 模板检查清单（C1~C19）+ 素材溯源专项（P1-1~P1-5）+ 方法论专项（M1~M5，分类标签与健康度）。

### 3.3 场景数量达标检查

对每个子功能点的 Given/When/Then 场景，逐项数：

```
子功能点 [编号]:
  主流程: N 个（要求 ≥1）          ← 不达标标注
  异常流程: N 个（要求 ≥3）        ← 不达标标注
  边界流程: N 个（要求 ≥2）        ← 不达标标注
```

不达标的处理：
- 资料区有足够素材但没写够 → 补充
- 资料区素材不足 → 已有场景正常写，不足场景标记 `⏳ 待确认：[缺失场景类型和原因]`

### 3.4 AC 模糊表述检查

全文搜索以下模糊词，逐一替换或标记：
- `功能正常` → 改为具体的可验证结果
- `体验良好` → 删除，写具体交互要求
- `快速` → 改为具体时限或标记 ⏳
- `稳定` → 改为具体的可用性指标或标记 ⏳
- `及时` → 改为具体时限或标记 ⏳
- `正确` → 改为具体的对错判断标准
- `来源：代码` → 检查该信息确实来自代码扫描，且扫描结果可复现

## 4. Phase 间交叉检查

### 4.1 编号一致性矩阵

| 对比项 | Phase 1 位置 | Phase 2 位置 | 检查方法 |
|--------|-------------|-------------|---------|
| 模块ID | 第1章 | 三件套文档索引 | 逐字对比 |
| 功能编号 | 第5章"功能点编号"列 | 三件套标题/REQ-ID/文件名 | 正则匹配 |
| 功能名称 | 第5章"功能点"列 | -Spec 1.1 / PM-Spec 目标 | 逐字对比 |
| 功能描述 | 第5章"功能描述"列 | Analyst-Spec 概述 | 语义一致性检查 |

### 4.2 排除范围一致性

- Phase 1 第6章声明的基线能力 → Phase 2 三件套不纳入
- Phase 2 某个功能点的排除项 → 不能与 Phase 1 第6章冲突
- Phase 2 不同功能点之间的排除项 → 不能互相矛盾

### 4.3 批量完成汇总检查

全部功能点 Phase 2 完成后，汇总检查：

| 检查项 | 方法 |
|--------|------|
| 功能点覆盖率 | Phase 1 第5章列出 N 个功能点 → Phase 2 完成 N 个 |
| 编号一致性 | 所有 Phase 2 目录的功能编号在 Phase 1 第5章均有注册 |
| 关联文档版本 | 所有 Phase 2 三件套引用的 Phase 1 版本一致 |

## 5. 自检问题处理流程

```
发现问题
    │
    ├── 编造内容（S1~S7、S13~S14未通过）
    │   └──> 立即删除编造内容 → 改为 ⏳ 待确认 → 登记到 Analyst-Spec 第七章
    │
    ├── 代码来源无法验证（S13~S14未通过）
    │   └──> 删除无法验证的代码来源内容 → 改为 ⏳ 待确认 → 登记到 Analyst-Spec 第七章
    │
    ├── 代码扫描遗漏（C11~C12未通过）
    │   └──> 重新扫描遗漏的代码文件 → 补充到 Spec → 重新检查
    │
    ├── 遗漏内容（C1~C17未通过）
    │   └──> 补充缺失内容 → 重新检查
    │
    ├── 口径不一致（S11~S12未通过）
    │   └──> 对齐 Phase 1 → 重新检查
    │
    └── 模板格式问题
        └──> 修正格式 → 重新检查
```

**关键原则**：发现编造内容时，**不允许"这段编得合理就保留"**。立即删除 + 标记 ⏳。

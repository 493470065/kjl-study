# 阶段3: 前后端开发（完整细节）

本文件包含阶段3的所有子步骤。**不随 skill 加载**，进入阶段3时由 agent 按需读取。

## 执行策略

| 场景 | 模式 |
|------|------|
| 仅一个 plan | 串行 |
| 前端+后端 plan，不同仓库 | **并行**（Agent 工具同时派发） |
| 前端+后端 plan，同一仓库 | 串行（先前端后后端） |

并行执行时，从 `references/agent-templates.md` 读取 Agent prompt 模板。

## 按 Task 执行（通用流程）

对每个 Task：

1. **保存检查点**：`git diff --name-only > .claude/task-checkpoint-{TaskN}.txt`
2. **读取 Task 描述和目标文件**
3. **执行修改**（先 Read 再 Edit）
4. **本地验证**（如 plan 中有验证步骤）
5. **失败回滚**：`git checkout -- {涉及文件}`，暂停让用户决定（参见 E-09）
6. **更新进度**：TaskUpdate 标记 completed
7. **更新状态文件**：将完成的 Task 追加到 `completedTasks`
8. **清理检查点**

**本阶段不执行 git commit。** 如 plan 代码片段与实际有出入，调整但保持意图。发现 plan 明显错误时暂停告知用户。

## Task 依赖处理

当 plan 中 Task 之间存在依赖关系时：

1. **显式依赖**：plan 中明确标注"依赖 Task N"的 Task，必须等待被依赖 Task 完成后再执行
2. **隐式依赖**：通过文件分析发现 Task B 修改的文件是 Task A 的产出（如 Task A 新增接口，Task B 调用该接口），按 plan 中的 Task 编号顺序执行
3. **无依赖**：同一 plan 中无文件交集的 Task 可按顺序逐个执行，无需特殊处理

**跨前后端依赖**：后端接口变更影响前端调用时，后端 Task 先行，前端 Task 依赖后端产出。这种情况在同一仓库串行模式下自然满足；不同仓库并行模式下，前端 Agent 在 plan 中会注明依赖的后端接口，前端 Agent 遇到不存在的接口时跳过该部分，在阶段5修复时补全。

## 代码片段适配策略

Plan 中的代码片段可能与实际文件存在差异，按以下策略处理：

| 差异类型 | 处理方式 |
|----------|---------|
| **import 路径不同** | 保留实际文件的 import 风格，仅替换目标方法/组件 |
| **方法签名变更** | 检查所有调用点是否需要同步调整，保持接口一致 |
| **上下文缺失** | Read 完整文件理解上下文后适配，不盲目插入 |
| **文件结构差异** | plan 指定的文件不存在时，搜索同名/同功能文件替代（参见 E-07） |
| **版本差异** | plan 基于旧版本但代码已升级（如 Vue2→Vue3），使用当前版本写法 |

**核心原则**：保持 plan 的修改意图（做什么），灵活适配实现方式（怎么做）。无法确定时暂停询问用户。

## 并行汇聚冲突检测

前后端不同仓库并行时无冲突风险。但以下场景需要注意：

### 前后端同仓库串行模式

后端 Task 执行完毕后，执行前端 Task 前检查：

```bash
# 检查后端修改是否影响前端依赖的文件
git diff --name-only HEAD origin/{fromBranch}
```

如果后端修改了前端也依赖的文件（如共享类型定义、常量文件），前端 Task 需要基于后端修改后的版本执行。

### 多 Agent 并行失败汇聚

如果任一 Agent 报告失败（参见 E-10）：
1. **保留成功方结果**，不自动回滚
2. **失败方回滚**到检查点：`git checkout -- {涉及文件}`
3. 向用户汇报失败原因和已完成方结果
4. 失败 Agent 的工作目录保留，由用户决定后续操作

**超时保护（参见 E-31）：** 单个 Task 执行超过 5 分钟时暂停并询问用户是否继续等待或跳过。

## 输出

- `.execute-state.json` 更新：`completedTasks` 记录已完成的 Task 列表
- worktree 中包含未提交的代码变更

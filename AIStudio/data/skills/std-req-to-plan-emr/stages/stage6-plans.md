# 阶段6: 生成实施计划

### 元信息

- **前置条件**: 阶段1-5已完成（设计文档已生成）
- **触发条件**: 自动执行（阶段5完成后进入）
- **预计耗时**: 2-5 分钟

### 输入

- 阶段5生成的 `前端设计.md`（如 `changeScope.frontend === true`）
- 阶段5生成的 `后端设计.md`（如 `changeScope.backend === true`）
- `state.json` 中的 `changeScope` 决定生成哪些 plan，`complexity` 决定生成方式

### 执行步骤

> **强制并行：当前端和后端 plan 都需要生成时，必须使用 Agent 工具并行生成。** 在一条消息中发出两个 Agent 调用，分别生成前端 plan 和后端 plan。

> **格式合同：** 生成的 plan 文件必须满足 std-plan-execute-emr 的解析要求：
> - Task 标题格式：`### Task N: [标题]`（正则：`/^#{2,3}\s+Task\s+\d+/i`）
> - 每个 Task 下包含 `- [ ]` 前缀的字段行
> - 必须包含：文件、操作、内容、验收 四个字段
> - 不可使用 `### 步骤` 等非标准标题格式
>
> 违反以上格式会导致 std-plan-execute-emr 无法正确解析和执行计划。

## 简单需求（`complexity === "simple"`）

直接基于设计文档生成 plan：

1. 读取对应的设计文档（`前端设计.md` / `后端设计.md`）
2. 将设计文档中的每个功能点转化为可执行的步骤
3. 每个步骤包含：依赖关系、风险评估、回滚策略、文件路径、操作、内容、验收标准
4. 保存为 `前端plan.md` / `后端plan.md`

**plan 格式：**
```markdown
# [前端/后端] 实施计划

## 需求背景
（从设计文档提取）

## 实施步骤

### Task 1: [标题]
- **依赖**: 无
- **风险**: 低 — [具体风险描述]
- **回滚**: `git checkout -- <file>`

- [ ] **文件**: `src/xxx/xxx.vue`
- [ ] **操作**: 新增/修改/验证/确认/测试
- [ ] **内容**: [具体变更描述，含代码片段]
- [ ] **验收**: [如何验证]

### Task 2: [标题]
- **依赖**: Task 1
- **风险**: 中 — [涉及数据库变更，需验证数据完整性]
- **回滚**: `git checkout -- <file>` + 数据库回滚脚本

- [ ] **文件**: `src/xxx/xxx.java`
- [ ] **操作**: 新增
- [ ] **内容**: [具体变更描述]
- [ ] **验收**: [如何验证]
```

## 复杂需求（`complexity === "complex"`）

使用 `superpowers:writing-plans` 技能，将设计文档转化为可执行的实施计划：

1. 读取阶段5生成的 `前端设计.md` / `后端设计.md`
2. 调用 `Skill` 工具，参数 `skill: "superpowers:writing-plans"`
3. 以前端/后端设计文档为输入，生成实施计划
4. **格式覆盖：** `superpowers:writing-plans` 生成的格式可能与本 skill 要求不完全一致，生成后必须检查并调整标题格式为 `### Task N:`，确保 checkbox 在每个字段前
5. 保存为 `前端plan.md` / `后端plan.md`

## 计划文件格式要求

- **标题必须使用 `### Task N: [标题]` 格式**，与 std-plan-execute-emr 解析兼容
- 每个任务是一个可独立完成的小步骤（2-5分钟）
- 包含具体的文件路径和代码片段
- 使用 `- [ ]` checkbox 语法跟踪进度（放在每个字段前）
- 每个步骤必须包含：依赖关系、风险评估、回滚策略
- 包含测试步骤
- 最后一个 Task 必须是验证/测试 Task
- **操作字段** 可选值：新增、修改、验证、确认、测试

#### 6.1 格式自检（强制）

plan 文件生成后，必须执行格式自检：

1. **标题检测**：使用正则 `/^#{2,3}\s+Task\s+\d+/im` 扫描生成的 plan，确认至少匹配到一个 Task 标题
2. **checkbox 完整性**：每个 Task 下必须包含 `- [ ]` 开头的行
3. **字段完整性**：每个 Task 必须包含 `**文件**`、`**操作**`、`**内容**`、`**验收**` 四个字段
4. **依赖链完整性**：除 Task 1 外，每个 Task 的 `**依赖**` 字段应指向一个已存在的 Task 编号
5. **格式合同校验**：确认无 `### 步骤` 格式的标题残留

如校验失败，立即修正 plan 文件后再保存。

### 输出

- `前端plan.md`（`changeScope.frontend === true` 时生成）
- `后端plan.md`（`changeScope.backend === true` 时生成）
- `state.json` 更新：`completedStages: [1,2,3,4,5]`

**输出数据契约（阶段6和 std-plan-execute-emr 依赖的字段）：**

每个 plan 文件必须满足的格式契约：
```markdown
# [前端/后端] 实施计划

## 需求背景
（从设计文档提取）

## 实施步骤

### Task N: [标题]
- **依赖**: 无 | Task N-1
- **风险**: 低/中/高 — [具体风险描述]
- **回滚**: `git checkout -- <file>`

- [ ] **文件**: `src/xxx/xxx.vue`     ← 必须是确切路径
- [ ] **操作**: 新增|修改|验证|确认|测试
- [ ] **内容**: [具体变更描述]         ← 含关键代码片段
- [ ] **验收**: [如何验证]             ← 可执行的验证步骤
```

**std-plan-execute-emr 解析依赖：**
- Task 标题正则: `/^#{2,3}\s+Task\s+\d+/i`（大小写不敏感）
- checkbox 字段: `- [ ]` 前缀，每行一个字段（文件/操作/内容/验收）
- 每个文件路径必须是相对于仓库根目录的有效路径
- 最后一个 Task 必须是验证/测试 Task

### 异常处理

| 场景 | 处理方式 |
|------|---------|
| 格式自检失败（标题格式不匹配） | 自动修正标题为 `### Task N:` 格式后重新保存 |
| 格式自检失败（checkbox 缺失） | 为每个 Task 补充 `- [ ]` 前缀的字段行 |
| 设计文档缺失某些章节 | 基于 API 契约推断缺失内容，在 plan 中标注为"待确认" |
| writing-plans 技能输出格式不一致 | 生成后强制执行格式覆盖（标题改为 Task N: 格式） |

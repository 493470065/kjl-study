## 一、目标

实现病历编辑与保存功能，覆盖病历内容编辑、暂存/保存、缺省值联动、快捷操作、编辑锁定与多人协同书写，确保病历内容书写准确、保存可靠、并发一致。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 病历切换保留已输入内容：书写未保存的病历切换后再返回，已输入内容不能清空 |
| BC-002 | 缺省值联动：入院记录和首次病程记录未提交时主诉/现病史/查体自动同步更新；已提交则不更新到已提交文书 |
| BC-003 | 数值型控件只能输入数字，非数值输入提示"请输入数值型内容" |
| BC-004 | 单客户端编辑模式：同一时间只允许一个账号一个电脑编辑一份病历 |
| BC-005 | 跨科多人同写一份病历文书（如手术风险评估表，多人编辑多人签名） |
| BC-006 | 外部粘贴控制：病历可分类型设置是否允许从外部复制内容进系统 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 病历内容保存走 content/data_element/save 接口 | 存储结构化数据 |
| TC-002 | 编辑器为自研编辑器（PG Editor），支持数值型/结构化元素 | 编辑器能力约束 |
| TC-003 | 快捷键读取个人设置 | 快捷键可配置 |

### 2.3 非功能性约束

#### 性能要求

| 指标 | 要求值 | 说明 |
|------|--------|------|
| 病历保存响应 | ⏳ 待确认 | 资料区无量化指标 |

| 要求 | 说明 |
|------|------|
| 编辑权限控制 | 诊疗组/科室/上级医师编辑权限 |
| 单客户端编辑锁定 | 防并发冲突 |

**医疗行业特殊要求**

| 要求 | 说明 |
|------|------|

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 病历编辑与保存是病历书写核心操作，数据一致性（缺省值联动/编辑锁定）直接影响病历准确性 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

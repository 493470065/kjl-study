## 一、目标

实现病历簿文书目录的展示能力，覆盖病历目录树展示、文书数量显示、患者签名标志（已签名/待签名）、目录展开收起快捷键、缩放按钮与非本科室目录颜色标识，确保医生无需打开病历即可直观识别签名状态、快速定位文书，减少遗漏、提升效率。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 文书总览列表中增加"待患者签名"和"已患者签名"两列，区分已签名与待签名 |
| BC-002 | 已签名显示绿色 ✓，待签名显示黄色 ○ |
| BC-003 | 无签名记录时默认显示为"待签名"；签名状态字段为 null 时显示为"待签名" |
| BC-004 | 按住"Alt+1"键可对病历目录进行收起和展开，鼠标悬浮 hover 时文字提示"Alt+1" |
| BC-005 | 目录导航的缩放按钮边缘线调整为有色并加粗，颜色跟随系统皮肤 |
| BC-006 | 病历目录背景色由写死的白色改为变量，支持换肤 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|
| TC-001 | 签名状态查询由"数据服务-签名记录"提供接口 |
| TC-002 | 换肤涉及编辑器背景色切换，编辑器无法自行对接框架换肤时需提供接口，前端监听换肤事件调用编辑器接口换肤 |

### 2.3 非功能性约束

#### 性能要求

| 指标 | 要求值 | 说明 |
|------|--------|------|
| 列表加载时间 | ≤ 3 秒 | 1000 条病历数据加载 |
| 筛选响应时间 | ≤ 1 秒 | 筛选操作响应 |

#### 安全要求

| 要求 | 说明 |
|------|------|
| ⏳ 待确认 | 本功能点安全要求未在资料区明确 |

**医疗行业特殊要求**

| 要求 | 说明 |
|------|------|
| 签名状态可视 | 减少遗漏未签名病历，降低医疗纠纷风险 |

#### 可用性要求

| 指标 | 要求值 | 说明 |
|------|--------|------|
| ⏳ 待确认 | - | 资料区未提供 |

## 三、验收标准

| AC编号 | 验收标准 | 验证方法 |
|--------|---------|
| AC-001 | 文书总览签名状态列正确显示：已签名显示绿色✓，待签名显示黄色○ |
| AC-002 | 病历目录中每个病历项右侧显示对应签名状态图标/文字 |
| AC-003 | 点击签名状态列标题排序时，待签名病历排在前面 |
| AC-004 | 患者无签名记录或签名状态为 null 时，默认显示"待签名" |
| AC-005 | 1000 条病历数据加载时间不超过 3 秒，筛选响应时间不超过 1 秒 |
| AC-006 | 按住 Alt+1 可收起/展开病历目录，hover 提示"Alt+1" |

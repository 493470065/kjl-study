## 一、目标

实现病历审签权限管理功能，覆盖上级医师审签、跨科审签、逐级签名、住院总审批、阅改签名与审签流程配置，确保病历审签合规、跨科可协同、流程可溯。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 病历上级加签需能按照职称逐级签名：参数"上级审签模式下主任医师是否可以加签"，主治审签通过后主任医师可审核加签，只能审签通过 |  |
| BC-002 | 跨科审签功能：支持审签其他科室的待我审签病历，监控类型配置为指定医师审签模式&没有科室权限的&指定本人审签 |  |
| BC-003 | 病历审签调用医务管理系统住院总人员设置接口，住院总需具备等同主任医师审批权限，支持自动同步医务院总名单 |  |
| BC-004 | 上级医生修改病历后需点击"阅改签名"才能保存修改内容，修改未保存需提醒"病历已修改，是否保存并签名" |  |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 审签通过需 EmrPermissionACL(permissionEnum=PASSED_REVIEW_AND_SIGN) 权限校验 | 审签权限控制 |
| TC-002 | 审签表 INPATIENT_EMR_REVIEW（审签状态/审签人/三级审签）、INP_EMR_REVIEW_ACTION（节点操作） | 审签记录 |
| TC-003 | 审签接口 review/approve|reject|withdraw、audit/save_audit_emr、get_has_next_audit_node | 审签端点 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 病历审签权限管理是权限管理核心起点（L1，H 要素），审签权限错误直接影响病历质量与法律效力，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

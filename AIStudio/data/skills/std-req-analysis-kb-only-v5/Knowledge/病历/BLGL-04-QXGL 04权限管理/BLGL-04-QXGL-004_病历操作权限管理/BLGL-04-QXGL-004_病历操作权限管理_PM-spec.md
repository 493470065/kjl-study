## 一、目标

实现病历操作权限管理功能，覆盖病历创建/编辑/删除/提交/撤回权限、整改医师修改权限、上级修改下级病历权限与病历编辑权限查询，确保病历操作合规、权限可查。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 环节质控整改医师病历修改权限：整改单无需审核时责任医师、三级管床医师获得所有需要整改病历文书的编辑权限 |  |
| BC-002 | 开启上级医生修改下级医生病历参数，审签流程中配置的文书上级医生具备修改病历文书和审核签名权限 |  |
| BC-003 | 临床诊断增加录入权限控制字段 diagnosisOnlyEdit，病历来源传 true |  |
| BC-004 | 诊断组件入参区分来源，医生可编辑诊断，护士不能编辑（含护理病历、病历协同页面） |  |
| BC-005 | 本人插入的诊断只有本人能够删除，删除后恢复预制样式 |  |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |

| TC-002 | 病历操作权限码 INP_EMR_PERMISSION_CODE + InpEmrOperationPermissionEnum | 操作权限 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 病历操作权限管理是权限管理操作管控核心（L1，H 要素），操作权限误判直接影响病历修改合规，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

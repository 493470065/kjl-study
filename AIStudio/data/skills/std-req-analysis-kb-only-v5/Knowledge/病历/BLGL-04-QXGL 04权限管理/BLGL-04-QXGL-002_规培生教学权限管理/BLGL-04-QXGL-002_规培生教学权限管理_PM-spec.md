## 一、目标

实现规培生教学权限管理功能，覆盖规培生/进修/实习医生书写病历权限、规培生签署病历、无资质账号限制与教学组功能，确保规培教学合规、无资质不越权。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 规培生判断：专业技术职称非医师/主治/副主任/主任（或为空）时，判断是否为当前患者规培/进修/实习医生 |  |
| BC-002 | 规培生权限：有新建、编辑、删除、暂存当前患者病历（自己创建的病历）的权限，没有提交权限 |  |
| BC-003 | 正式医生可提交规培生写病历 |  |
| BC-004 | 无资质账号（学生）不能创建入院记录以及首次病程记录 |  |
| BC-005 | 住院病历新增规培生书写病历、签署病历的功能 |  |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 病历编辑权限查询接口 emr_permission/query/by_example | 规培权限 |
| TC-002 | 职称权限表 INP_EMR_EXPERTISE_PERMISSION（expertiseCode/inpEmrPermissionCode） | 职称权限 |

### 2.3 非功能性约束

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P1 | 规培生教学权限管理为教学场景功能，需求数较少（12条）非核心，但无资质越权影响病历安全 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

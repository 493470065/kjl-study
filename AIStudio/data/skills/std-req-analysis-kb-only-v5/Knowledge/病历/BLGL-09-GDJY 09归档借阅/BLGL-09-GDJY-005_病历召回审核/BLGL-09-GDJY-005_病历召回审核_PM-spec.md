## 一、目标

实现病历召回审核功能，覆盖召回多级审批（通用/首页分开）、审核修改召回原因、审核意见展示、召回审核查询与批量审核，确保召回申请审批合规、可溯。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 参数"允许修改召回申请的审核节点"，配置的审核节点可修改申请单召回原因，审核通过更新修改内容，不通过不更新 |  |
| BC-002 | 病案首页召回是否单独审批参数，为是时召回审批维护分为通用审批和首页审批，可分别配置流程 |  |
| BC-003 | 召回审核流程新增质控科审核，质控科审核是最后一个审核人 |  |
| BC-004 | 召回审核界面展示审核人员审核意见内容（不只显示"审核通过/退回"） | 6 |
| BC-005 | 未选中任何召回原因时审核通过按钮置灰 |  |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 病历召回审核是召回申请生效的审批关口，审批流程/权限错误直接影响病历修改合规，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

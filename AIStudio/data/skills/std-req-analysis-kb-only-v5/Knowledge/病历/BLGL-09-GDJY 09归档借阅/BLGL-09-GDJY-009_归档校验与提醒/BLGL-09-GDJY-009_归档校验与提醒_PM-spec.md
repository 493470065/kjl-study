## 一、目标

实现归档校验与提醒功能，覆盖归档前完整性校验、归档缺项提醒（未签名/缺文书/未审签）、手动归档消息提醒与 PDF 生成保障，确保归档完整、提醒及时、PDF 可靠。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 只有参数"病案归档是否开启与卫宁60病案系统对接模式（EG005）"=否才能启用病历归档提醒功能；"是否开启病历归档提醒"参数是/否默认否 |  |
| BC-002 | 归档定时任务查询待归档患者，查询未签名（文书状态={新建、草稿、不能打印}）和缺文书（有未处理待书写任务）情况，给住院医生和主治医生发送站内信 |  |
| BC-003 | "是否开启手动归档的消息提醒"参数与 EG008（病历不会自动归档的临床科室）联动，手动归档时间消息提醒取 EG001/EG002 设置时间 |  |
| BC-004 | AT002 配置"未审签"时，查询预归档患者是否存在审签流程未结束的病历，存在时发送提醒加"未完成审签病历xx份"；AT003 配置责任医生时提醒发送给责任医生 | 5 |
| BC-005 | 归档缺项提醒消息显示患者剩余归档天数，从只发一次改为每天发送且自动作废上一次消息 | 1 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|

| TC-002 | nodePDF 支持特殊字符 U+2600-U+26FF | PDF 特殊字符显示（1） |
| TC-003 | 归档校验接口 emr_filing_by_hand/check（入参 InpatientEmrSetInputAO，出参 InpEmrFilingCheckOutputVO） | 归档前校验 |
| TC-004 | 批量归档校验接口 emr_filing_by_hand/batch_check（入参 InpEmrBatchArchiveCheckInputAO） | 批量归档校验 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 归档校验与提醒是归档质量保障（L1），校验缺失/提醒失效直接影响病案完整性与归档合规，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

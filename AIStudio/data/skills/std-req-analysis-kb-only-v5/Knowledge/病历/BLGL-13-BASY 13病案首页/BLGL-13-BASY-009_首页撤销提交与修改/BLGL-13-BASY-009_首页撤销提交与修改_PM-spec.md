## 一、目标

实现病案首页撤销提交与修改的流程控制，覆盖撤销提交接口对接（60病案/WiNEX病案）、撤销申请审批、编码中撤销限制、提交并打印后撤销限制，确保首页变更受控且数据安全。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 首页撤销提交需对接病案系统撤销接口 |
| BC-002 | 病案室要求已录入/审核通过的首页撤销前必须先申请 |
| BC-003 | 编码状态=编码中（3）时不能撤销提交 |
| BC-004 | 首页提交并打印后禁止医生自行撤销，需申请审批 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 撤销提交前需调撤销首页判断接口 | |
| TC-002 | 不允许直接撤销时返回URL打开申请网页 | |

### 2.3 非功能性约束

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 首页撤销控制是变更安全核心，不做则已提交首页可随意撤销 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

## 一、目标

实现会诊计费功能，根据会诊类型、医生职称等规则自动/手动计算会诊费用，支持医生自主选择是否计费、医保控费校验、会诊费用记账人确认，覆盖急诊自动生成费用医嘱、抗菌药物会诊免计费、计费规则可配置（按科室计费/按类型一口价/按职称计费/按科室数量阶梯计价/不计费）等场景，确保会诊计费的准确性、合规性与流程闭环，保障会诊费用有效纳入患者费用体系。

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 会诊计费规则支持多种计费模式配置：按实际会诊科室计费、按会诊类型一口价、按科室数量阶梯计价、按人员职称计费、不计费。住院、门诊、急诊会诊可分别配置（来源：资料区会诊管理功能清单 FUNC_024） |
| BC-002 | 计费触发节点可配置，支持在以下节点触发计费：申请单发送、审核完成、签到、接收、答复、会诊完成。支持多院区设置不同的计费规则（来源：资料区会诊管理功能清单 FUNC_025） |
| BC-003 | 医生可自主选择是否计费，计费操作非强制，支持医生在会诊流程中根据实际情况决定是否触发计费（来源：需求背景） |
| BC-004 | 会诊费用按医生职称分类计费：正高职称（主任医师）与副高职称（副主任医师）执行不同的计费标准，计费标准由计费参数配置驱动（来源：需求背景） |
| BC-005 | 医保控费信息显示：在会诊计费时需展示医保控费相关信息，供医生参考，医保控费校验结果影响计费确认（来源：需求背景 + 参数配置"住院会诊费用医保审核功能"） |
| BC-006 | 会诊费记账人应为接收方（受邀科室/医生），而非申请方，计费账单的记账主体为接收会诊的科室/医生（来源：需求背景） |
| BC-007 | 邀请本科室抗菌药物会诊专家审批时不收取会诊费，即同一科室内的抗菌药物会诊不计费（来源：需求背景） |
| BC-008 | 急诊科发起会诊时自动生成费用医嘱，无需医生手动操作计费，执行科室自动设为会诊科室（来源：需求背景 + 关联模块 BLGL-05-HZGL-001 会诊申请 TC-004） |
| BC-009 | 会诊计费服务不绑定计费策略，计费策略由配置参数驱动，服务层仅执行计费规则计算，不硬编码计费策略逻辑（来源：需求背景） |
| BC-010 | 会诊医嘱未计费状态影响预出院校验：会诊医嘱未完成计费时，患者预出院校验不通过，系统提示"会诊医嘱未计费，请完成计费后再办理出院"（来源：需求背景） |
| BC-011 | 会诊计费支持撤销计费操作，在对应节点（如撤销申请、撤销签到等）可进行撤销计费，撤销后的计费记录保留审计轨迹（来源：资料区会诊管理功能清单 FUNC_026） |
| BC-012 | 会诊计费与HIS医嘱系统对接，计费结果同步至HIS系统生成正式费用账单，会诊费用医嘱的执行科室为受邀会诊科室（来源：资料区模块级Spec 7.2 外部系统关联） |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 会诊账单数据实体为 EMR_CONSULT_BILLING（8字段），计费参数配置实体为 EMR_CONSULT_BILLING_PARAM（7字段）和 EMR_CONSULT_BILL_DETAIL_PARAM（8字段）（来源：模块级Spec 8.3 数据实体清单） | 计费数据需持久化，保障账单数据完整性和可追溯性 |
| TC-002 | 会诊计费对接HIS医嘱系统，费用医嘱同步需通过HIS接口完成，计费结果实时同步至HIS费用模块（来源：模块级Spec 7.2 外部系统关联） | 会诊费用需纳入患者住院总费用体系，HIS为核心计费系统 |
| TC-003 | 会诊计费服务不绑定计费策略，计费规则由 EMR_CONSULT_BILLING_PARAM 配置表驱动，服务层通过策略模式加载计费规则，新增计费模式无需修改代码（来源：需求背景） | 计费策略因医院管理要求而异，需支持灵活配置，避免硬编码 |
| TC-004 | 急诊科自动生成费用医嘱需与HIS医嘱系统对接，通过医嘱接口自动创建会诊费用医嘱，执行科室设置为会诊科室（来源：需求背景 + 关联模块 BLGL-05-HZGL-001 会诊申请） | 急诊会诊场景要求快速响应，自动生成费用医嘱减少人工操作 |
| TC-005 | 医保控费校验需对接医保系统接口，获取医保控费信息并展示，计费时需校验医保控费规则（来源：需求背景 + 参数配置"住院会诊费用医保审核功能"） | 医保控费是医院合规管理要求，需实时校验 |
| TC-006 | 会诊计费模块位于 v2-write（后端书写模块）和 v2-setting（后端配置模块），前端页面位于 pages/setting/setting-billing/（来源：模块级Spec 8.2 模块-代码映射表） | 计费操作与会诊书写流程关联，计费配置在配置模块维护 |

### 4.2 明确边界

- **本次需求涉及的角色**：
  - 申请医生（选择是否计费、查看计费状态）
  - 会诊医生/受邀医生（计费接收方，记账人）

  - 护士（查看计费状态、触发计费操作）

### 5.1 方案决策

| 决策ID | 决策项 | 方案A | 方案B | 选择 | 理由 | 决策人 | 日期 |
|--------|--------|-------|-------|------|------|--------|------|
| D-001 | 计费策略绑定方式 | 计费策略由配置参数（EMR_CONSULT_BILLING_PARAM）驱动，服务层通过策略模式加载，新增计费模式无需修改代码 | 计费策略硬编码在计费服务中，新增计费模式需修改代码 | 方案A | 需求明确要求"会诊计费服务不绑定计费策略，优化提示"，计费策略因医院管理要求而异，需支持灵活配置，避免因策略变更导致代码修改和重复发版 | 产品经理 | 待确认 |
| D-002 | 计费触发方式 | 支持两种触发方式：① 自动触发（按配置节点自动计费）；② 手动触发（医生自主选择是否计费）。两种方式并存，按配置和医生选择决定 | 仅支持自动触发计费 | 方案A | 需求要求"医生自主选择是否计费"，同时急诊场景要求自动计费，两种方式并存满足不同场景需求 | 产品经理 | 待确认 |
| D-003 | 医保控费校验时机 | 计费时实时校验医保控费规则，展示控费信息，医生确认后完成计费 | 计费完成后异步校验，校验结果通过通知告知医生 | 方案A | 医保控费校验应在计费确认前完成，避免计费后因医保控费不通过导致退费操作；实时校验更符合医院财务合规要求 | 产品经理 | 待确认 |
| D-004 | 预出院校验策略 | 会诊医嘱未计费时，预出院流程校验不通过，需完成计费后方可办理出院 | 预出院仅提示会诊医嘱未计费，不强制阻断 | 方案A | 需求明确要求"会诊医嘱未计费无法查询与预出院校验缺失"，会诊费用作为住院费用的一部分，未完成计费可能导致财务结算遗漏，需强制阻断 | 产品经理 | 待确认 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P1 | 会诊计费是会诊管理模块的L2重要功能，是会诊完成后的财务结算环节，直接影响会诊费用的准确性和合规性。C-DARHS评估为4/6（C✅D✅A✅R✅H❌S❌），满足L2重要功能定位。会诊计费虽然不涉及患者安全（H❌），但涉及财务合规和医保控费，是医院会诊管理不可缺失的环节。部分核心场景（如急诊自动计费、预出院校验）具有较高优先级，但整体可放在会诊答复与记录功能之后交付。 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

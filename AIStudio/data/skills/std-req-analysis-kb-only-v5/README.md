# std-req-analysis-kb-only-v5

医疗信息系统知识库需求分析 skill（病案 + 病历）—— **不扫码版**。

基于 **std-req-analysis-emr-v5** 改造，核心差异：

| 对比项 | std-req-analysis-emr-v5 | std-req-analysis-kb-only-v5 |
|--------|------------------------|----------------------------|
| 代码扫描 | 必须（策略A/B/C） | **不扫描代码** |
| 现状验证 | 代码仓库 + 知识库 | **仅知识库**（功能清单/Spec文档/参数资料） |
| 代码路径依赖 | 需要 | **不需要** |
| 知识库使用 | 辅助参考 | **主要参考依据** |

## 版本历史

| 版本 | 日期 | 变更内容 |
|------|------|---------|
| v1.0.0 | 2026-08-23 | 从 `std-req-analysis-emr-v5` 分离创建，去除代码扫描步骤（策略A Graphify/策略B Grep/策略C Mock搜索），替换 R5 为知识库核查规则（R5-KB），基于知识库进行现状判断和功能验证。 |

## 结构说明

| 目录 | 说明 |
|------|------|
| `SKILL.md` | 技能入口。包含适用边界、强制规则、完整执行流程、失败降级和参考索引 |

## 用途

- 基于 TFS 需求号完成正式产品业务分析，**不扫描代码**。
- 读取 TFS 描述、附件、图片、前置/相关工作项、**知识库功能清单**、参数资料和 Spec 文档。
- 生成并回写 `Winning.Demand.Analysis`。
- 追加 `AI-ANALYSIS` 和 `std-req-analysis-kb-only-v5` 标签。
- 上传最终版 `产品业务分析.md`。
- 默认检查并创建 `需求分析_<需求号>` 子任务，已存在则跳过。

## 复制到其他电脑后的配置

### 1. TFS MCP

目标环境必须已配置可读写 TFS 的 MCP 能力，至少需要支持：

- 读取工作项详情；
- 列出和下载附件；
- 读取相关/父子工作项；
- 从 Markdown 文件路径回写 `Winning.Demand.Analysis`；
- 更新 `System.Tags`；
- 上传附件；
- 创建或关联需求分析任务。

如果 TFS MCP 不可用，本技能会停止，不会改用未认证脚本或旧文件继续分析。

### 2. 知识库

本技能不依赖代码仓库，但需要 `Knowledge/` 目录下的功能清单和 Spec 文档。如果目标电脑缺少知识库文件，分析时会在正文中备注"知识库参考有限，建议补充复核"。

### 3. 参数库（可选）

参数库配置默认使用团队共用只读连接，通常不需要修改：

- 病案参数：`config/ma-parameter-db.json`
- 病历参数：`config/inpatient-emr-parameter-db.json`

如果目标电脑无法访问对应数据库，分析时会优先使用 `references/Param/` 下的 CSV 参数资料，并记录参数查询失败原因。

## 边界

- 必须有 TFS 需求号。
- 只以当前 TFS 工作项、附件/图片、前置/相关工作项、知识库功能清单、参数资料和 Spec 文档为输入；不依赖代码仓库扫描、旧技能或本地过程文件。
- 不生成研发实现方案、接口设计、数据库设计或开发计划。
- 不处理时限讨论。
- 不创建临时澄清附件。

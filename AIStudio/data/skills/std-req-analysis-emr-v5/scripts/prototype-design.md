# 原型设计指南（Pencil）

本指南仅在需求分析阶段需要界面原型时使用。原型用于帮助客户、产品和研发确认交互边界，不替代 `Winning.Demand.Analysis` 正文。

## 触发条件

满足任一条件时，判断是否需要原型：

- 新增界面。
- 界面布局重大修改。
- 配置界面修改较大。
- 用户交互流程变更。
- 客户提供的截图、草图或竞品图需要转成目标界面。

纯后端逻辑、参数值调整、文案微调、字段小范围增删且交互不变时，通常不做原型，只在需求分析正文写清界面要求。

## 输出目录

使用本次运行目录：

```text
<需求号>/<yyyyMMdd-HHmmss>/
```

不要写死个人电脑或某个产品的绝对路径。不要把完整 HTML 原型混入 `Winning.Demand.Analysis` 正文；正文只写原型结论、页面区域、字段、按钮、交互和验收标准。

## 设计流程

1. 判断是否需要原型，并在 `notes.md` 记录触发原因。
2. 基于需求输入、图片、现有界面和代码验证结论，使用 Pencil MCP 工具设计原型。
3. 原型必须经用户确认；未确认前不要把原型当成确定方案写入 TFS。
4. 用户确认后，生成 HTML 原型文件，并按 TFS MCP 能力上传到工作项附件。
5. 将确认后的原型要点同步到 `产品业务分析.md` 的产品设计、原型或验收标准章节。

## Pencil 使用要求

- 使用现有应用的信息架构和控件风格，不做营销页或过度装饰。
- 页面必须能表达入口位置、字段来源、显示条件、按钮动作、权限边界和异常状态。
- 多页面或多状态原型要拆成清晰的 screen，并命名为业务可读名称。
- 生成 HTML 前检查文字不重叠、字段不截断、按钮和表格状态可读。
- 原型源文件、HTML 文件和确认记录都放在本次运行目录，不写入 `Knowledge/`。

## TFS 上传规则

- 只上传用户确认后的 HTML 原型文件。
- 文件名包含需求号、页面名和版本，例如 `<需求号>-原型-配置界面-v1.html`。
- 如果用户要求继续调整，先更新 Pencil 原型，再重新生成 HTML 并上传新版本；不要覆盖已确认版本。
- 上传后在 `notes.md` 记录附件名和确认状态。

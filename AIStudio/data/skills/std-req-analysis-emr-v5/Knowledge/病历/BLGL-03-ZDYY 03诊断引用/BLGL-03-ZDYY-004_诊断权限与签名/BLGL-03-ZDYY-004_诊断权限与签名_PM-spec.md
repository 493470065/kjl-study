## 一、目标

实现诊断权限与签名功能，覆盖录入/来源/类型权限控制、确定/补充诊断上级加签与职称比较、诊断签名及签名优化，确保诊断引用与签名合规。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 临床诊断增加录入权限控制字段 diagnosisOnlyEdit，病历来源传 true |
| BC-002 | 诊断组件打开时入参区分来源，医生可编辑诊断，护士不能编辑（含护理病历、病历协同页面） |
| BC-003 | 医师上下级关系通过员工专业技术职务判断：主任医师＞副主任医师＞主治医师＞医师 |
| BC-004 | 上级加签后签名样式"上级医师姓名/下级医师姓名"，职称高的放在前面 |
| BC-005 | 加签失败时橙色提醒"该诊断上级医师已签名，无操作权限！"，不更新诊断 |
| BC-006 | 诊断签名校验参数与正常签名一致：CA_SIGNATURE、PICTURE_SIGNATURE、COMMON071、COMMON114、COMMON145 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 诊断组件入参区分来源 | 医生/护士权限区分 |
| TC-002 | 手动插入入院记录的诊断需记录签名人和签名人职称 | 加签职称比较 |

| 优先级 | 说明 |
|--------|------|
| P0 | 诊断权限与签名是诊断引用合规保障，权限误判/签名丢失直接影响医疗合规，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高

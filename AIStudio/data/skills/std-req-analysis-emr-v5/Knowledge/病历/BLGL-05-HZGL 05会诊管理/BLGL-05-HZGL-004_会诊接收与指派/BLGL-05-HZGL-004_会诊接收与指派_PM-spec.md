## 一、目标

实现会诊任务的接收与指派功能，院总/科室管理员可根据会诊类型、专业匹配度、医生排班等因素，将会诊任务指派给具体会诊医生；受邀科室/医生可接收会诊任务并查看患者病历信息，支持撤销接收操作。通过职称限制（主治医师及以上接收常规会诊）、自接收控制（不能接收自己发起的会诊）、科室全员可见（会诊接收菜单支持科室全员查看及处理指定医生会诊申请）、受邀科室筛选（会诊接收查询增加受邀科室选择）等规则，确保会诊指派与接收的合规性、高效性与可追溯性。

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 会诊接收时需控制不能接收自己发起的会诊申请，系统应校验当前登录医生是否为会诊申请人，如是则禁止接收并提示（来源：资料区需求ID 1580340） |
| BC-002 | 限制主治医师以下职称医生接收常规会诊，仅主治医师及以上职称的医生可执行常规会诊的接收操作（来源：资料区需求ID 1628426） |
| BC-003 | 会诊接收菜单需支持科室全员查看及处理指定医生会诊申请，不受"指定医生"限制，科室全体成员均可查看本科室会诊任务并处理（来源：资料区需求ID 1638561） |
| BC-004 | 会诊接收查询需增加受邀科室选择条件，支持按受邀科室筛选会诊接收列表（来源：资料区需求ID 1551452） |
| BC-005 | 会诊接收查询支持急会诊特殊颜色标记，在接收列表中急会诊以醒目颜色标记区分（来源：资料区需求ID 1625791） |
| BC-006 | 院总/科室管理员可按需将会诊任务指派给具体会诊医生，指派时需考虑医生职称、专业方向、排班情况等因素（来源：需求） |
| BC-007 | 会诊接收支持撤销接收操作，撤销后会诊任务恢复至待接收状态，其他医生可重新接收（来源：需求） |
| BC-008 | 会诊患者需判断接收状态，未接收的患者不允许进入患者详情界面，医生必须先接收会诊任务方可查看患者病历（来源：资料区需求ID 1617729） |
| BC-009 | 会诊费记账人应为接收方，即接收会诊任务的医生为会诊费用的记账责任人（来源：资料区需求ID 1682399） |
| BC-010 | 会诊接收后，会诊申请单的病历节点上需记录接收签到时间，作为会诊流程的时间节点数据（来源：资料区需求） |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |

| TC-005 | 新老会诊系统过渡期间，会诊接收与指派接口需兼容老接口（v1）同步，确保数据双向一致（来源：需求） | 保障新老系统过渡期间数据一致性 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P1 | 会诊接收与指派是会诊管理模块的L2重要功能，是会诊申请审核通过后的关键衔接环节。只有完成会诊接收与指派，受邀医生才能进入会诊签到、答复等后续流程。C-DARHS评估为4/6（C✅D✅A✅R✅H❌S❌），满足L2重要功能定位。本功能点涉及多个业务规则约束（职称限制、自接收控制、科室全员可见、急会诊标记等），虽不直接涉及患者安全（H❌），但直接影响会诊流程的效率和合规性。 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

## 一、目标

实现会诊申请功能，覆盖科间会诊、全院会诊、MDT会诊、院外会诊、抗菌药物会诊、急诊会诊六种会诊类型的申请创建、暂存、提交、撤销与删除全流程，保障申请医生根据患者病情需要准确选择会诊类型、邀请科室/医生、填写会诊目的/理由，并触发送达通知，确保会诊申请流程的完整性、合规性与可追溯性。

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 会诊申请支持六种会诊类型：科间会诊、全院会诊、MDT会诊、院外会诊、抗菌药物会诊、急诊会诊。其中住院医生站科间会诊时仅允许选择单一科室 |
| BC-002 | 会诊申请撤销删除后，受邀科室仍可查询该会诊申请记录，不可物理删除，采用逻辑删除标记 |
| BC-003 | 患者出区后仍可申请会诊，不受患者当前住院状态限制 |
| BC-004 | 会诊申请需防止重复发送会诊医嘱，同一患者同一会诊类型在有效期内不可重复提交 |
| BC-005 | 会诊授权配置控制：通过会诊授权参数控制哪些科室/医生可以发起会诊申请，未授权的用户不可提交申请 |
| BC-006 | 新会诊流程中，当参数PAR00235为1时，受邀科室不指定医生，查询页默认不勾选本人 |
| BC-007 | 会诊申请单标题需增加会诊科室名称，以区分不同科室的会诊单 |
| BC-008 | 会诊申请列表展示字段：科室名称、会诊目的、会诊医生、病人状态、床位号、病区 |
| BC-009 | 急会诊需特殊颜色标记，在列表和详情中进行醒目展示 |
| BC-010 | 支持按职称筛选医生、按科室筛选医生；支持拼音/五笔检索员工 |
| BC-011 | 会诊申请中，选择住院类型后，后续医生仍显示全部就诊类型，不受住院类型筛选影响 |
| BC-012 | 住院医生站会诊界面新增床位号与病区信息显示 |
| BC-013 | 会诊申请默认筛选与自定义排序规则，支持用户自定义排序方式 |
| BC-014 | 多学科会诊（MDT）中按表格分行显示多个科室、医生及职称信息 |
| BC-015 | 申请人答复会诊（逆向流程）：在受邀医生未答复时，申请人可对会诊申请进行答复操作 |
| BC-016 | 会诊记录单右键增加短语收藏功能，方便医生快速录入常用短语 |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 会诊申请删除采用逻辑删除（通过状态字段标记），不可物理删除，撤销后受邀科室仍可查询 | 保障会诊记录的可追溯性和审计合规性 |
| TC-002 | 会诊申请相关接口需兼容老接口（v1）同步，同时支持新接口（v2），确保数据双向同步 | 新老系统过渡期间需保证数据一致性 |
| TC-003 | 拼音/五笔检索员工需依赖主数据系统（MDM）提供的员工检索接口 | 员工信息由主数据系统统一维护 |
| TC-004 | 急诊科发起会诊时自动生成费用医嘱，执行科室设为会诊科室，需与HIS医嘱系统对接 | 会诊费用自动计费，减少人工操作 |
| TC-005 | 会诊申请数据实体为EMR_CONSULT_APPLY（41字段），为核心业务主表 | 来源：代码仓库扫描 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 会诊申请是会诊管理模块的起点功能，是端到端会诊流程的核心入口。没有会诊申请，后续的审核、接收、指派、签到、答复、计费等流程均无法启动。C-DARHS评估为5/6（C✅D✅A✅R✅H✅S❌），满足L1核心功能定位。 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

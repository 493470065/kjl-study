## 一、目标

实现会诊审核功能，审核人员对已提交的会诊申请进行审核，支持审核通过/驳回操作并记录审核意见，支持多级审核流程（可配置审核层级与审核角色），展示待审核列表与审核历史记录，支持CA签名，涵盖特殊级抗菌药物会诊审核场景，确保会诊审核流程的合规性、可追溯性与流程闭环。

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 |
|--------|---------|
| BC-001 | 审核流程支持多级配置（如一级审核、二级审核），审核层级与审核角色通过会诊审核流程配置参数定义（来源：资料区需求 + 代码 EMR_CONSULT_AUDIT_PARAM 审核参数表） |
| BC-002 | 审核人员按审核流程配置确定，非所有有权限的医生均可审核，审核角色范围由医务科/科室管理员在审核流程配置中维护（来源：需求） |
| BC-003 | 审核通过后会诊申请进入"待接收"状态，审核驳回后会诊申请退回，申请医生可查看驳回原因并重新提交（来源：代码状态机 AUDIT_STATUS 0→1 审核通过 / 0→2 审核驳回） |
| BC-004 | 特殊级抗菌药物会诊审核需填写抗菌药物使用理由，且受抗菌药物使用管理规定约束，审核通过后方可执行抗菌药物使用（来源：需求） |
| BC-005 | 会诊审核记录不可删除或修改，审核意见、审核人、审核时间等数据作为审计轨迹永久保留（来源：需求） |
| BC-006 | 审核人员可查看会诊申请详情（患者信息、会诊类型、受邀科室/医生、会诊目的/理由等），基于完整信息做出审核决策（来源：需求） |
| BC-007 | 会诊审核支持CA签名，审核通过时需进行CA签名，签名后的审核记录具有法律效力（来源：需求） |

### 2.2 技术约束

| 约束ID | 约束内容 | 原因 |
|--------|---------|------|
| TC-001 | 审核结果变更会诊申请状态（AUDIT_STATUS），审核记录写入 EMR_CONSULT_AUDIT 表（19字段），审核详情写入 EMR_CONSULT_AUDIT_DETAIL 表（7字段），多级审核时逐级记录（来源：代码） | 会诊审核数据实体为系统核心业务数据，需保障数据完整性和一致性 |
| TC-002 | 审核流程配置参数存储在 EMR_CONSULT_AUDIT_PARAM 表（5字段）和 EMR_CONSULT_AUDIT_DETAIL_PARAM 表（17字段），审核流程配置由 v2-setting 模块管理（来源：代码） | 审核流程的可配置性依赖参数配置表，配置变更需在审核流程前完成 |
| TC-003 | 会诊审核通知（审核通过/驳回）需对接消息中心，推送至申请人诊疗协作框（来源：需求） | 确保申请人及时获知审核结果 |
| TC-004 | 会诊审核CA签名需对接CA签名服务，签名后的审核记录满足电子签名法合规要求（来源：需求 + 关联模块 BLGL-15-QM） | CA签名涉及第三方认证服务集成 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 会诊审核是会诊管理模块的L1核心功能，是会诊申请后的关键审核环节，审核通过方可进入接收/指派/答复等后续流程，审核驳回则流程终止。C-DARHS评估为5/6（C✅D✅A✅R✅H✅S❌），满足L1核心功能定位。无审核环节的会诊流程将导致合规风险，特别是特殊级抗菌药物会诊场景下，审核是法定前置条件。 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

## 一、目标

实现病历召回申请功能，覆盖召回原因选择与管控、便捷操作模式、撤销召回、转出科室召回与质控整改自动召回，确保医生对已归档病历高效、合规地发起召回申请。

---

## 二、约束

### 2.1 业务约束

| 约束ID | 约束内容 | 来源 |
|--------|---------|------|
| BC-001 | 未选择召回原因不允许召回，选择召回原因后赋予对应操作权限 | 7 |
| BC-002 | 召回参数配置增加"是否启用便捷操作模式"，开启后首列复选框多选联动 |  |
| BC-003 | 病历召回查询和我的申请列表，申请由登录用户发起且未经任何人审核时，可"撤回申请" |  |
| BC-004 | 转出科室患者可通过"就诊科室"筛选查询并申请召回，记录申请人当前登录科室为申请科室 |  |
| BC-005 | 终末质控整改单发送后自动召回需要整改的病历文书，召回打印原因默认"病历补打印"，修改原因默认"质控整改" |  |
| BC-006 | COMMON111 控制召回申请操作模式（单选/复选全部/新增/修改/打印/全选） | 5 |

## 六、优先级

| 优先级 | 说明 |
|--------|------|
| P0 | 病历召回申请是归档借阅核心操作入口（L1），召回原因管控/转出科室/质控联动直接影响病历修改合规，必须交付 |

**优先级定义**

- **P0（核心必须）**：不做则需求无意义，必须本次交付
- **P1（重要但非核心）**：影响用户体验或效率，本次交付优先级高
- **P2（附加价值）**：锦上添花，可延后到后续版本

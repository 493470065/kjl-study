# 8. 原型设计（按需触发）

> ⚠️ **触发条件**：新增界面、界面布局重大修改、配置界面修改较大、用户交互流程变更

涉及上述 UI 变更时，必须设计原型；纯后端/配置类需求不涉及原型。

## 设计流程

1. 判断是否需要原型
2. 使用 Pencil MCP 工具设计原型（参考 `scripts/prototype-design.md`）
3. **原型确认**（必须经用户确认）
4. 导出原型为 **HTML 格式**（支持简单交互）
5. 上传 HTML 原型文件到 TFS 附件

## 处理规则

- 原型设计按需触发，不是所有需求都输出原型
- 原型必须先给用户确认，确认前不上传 TFS 附件
- 用户确认后，导出原型并上传 TFS 附件；正文只记录原型附件名称、页面范围和核心变更点
- 原型设计细则见 `scripts/prototype-design.md`

## 输出格式要求

- 原型文件命名：`原型_<需求号>.html`
- 输出目录：本地 `.ai-work/requirements/<需求号>/<yyyyMMdd-HHmmss>/prototype/`
- 使用 Pencil MCP 的 `export_nodes` 工具导出为 HTML 格式
- **交互支持**：HTML 原型需包含以下简单交互能力
  - 页面跳转/弹窗打开关闭
  - 按钮点击状态变化
  - Tab/页签切换
  - 表单输入框聚焦
  - 下拉选择展开收起
  - 列表项悬停高亮
- 上传时使用 TFS MCP 的 `upload_attachment` 工具，将 HTML 文件上传到当前工作项

## 上传步骤

1. 确认 HTML 文件已生成且内容完整
2. 调用 `upload_attachment` 上传到 TFS 工作项
3. 在 `产品业务分析.md` 的原型章节记录附件名称和链接
